## Design Context

### Users
`mdhub` is for PMs, POs, planners, designers, and developers working in small collaborative teams.
They use the product to keep epics, tasks, and markdown documents connected in one project context so planning intent and execution stay aligned.
The interface should support focused work, quick scanning, and low-friction navigation across structured project artifacts.

### Brand Personality
The brand personality is clear, disciplined, and restrained.
The product should feel calm, trustworthy, and highly legible, with the quiet confidence of a mature product system rather than a branded marketing surface.
It should help teams feel organized and in control without looking sparse, generic, or visually noisy.

### Aesthetic Direction
Use a refined, system-first visual language inspired by shadcn's strengths: neutral palettes, crisp borders, restrained radii, clean typography, and compositional discipline.
Favor monochrome and near-monochrome surfaces over colorful UI, using color sparingly and only where it carries semantic meaning or interaction emphasis.
Maintain full parity between light and dark themes so the product feels like the same system in both modes, not two different visual identities.
Avoid excessive card nesting, decorative surface treatments, or low-density layouts that make the interface feel vague or under-structured.

### Design Principles
1. Prioritize clarity over decoration.
Every screen should be understandable at a glance, with strong hierarchy, obvious actions, and minimal visual clutter.

2. Build with neutral system primitives first.
Prefer borders, spacing, typography, and layout to create hierarchy before introducing color, shadows, or ornament.

3. Increase density without losing calmness.
The interface should feel information-rich and useful, but never cramped. Avoid empty expanses, weak grouping, or layouts that hide structure behind too much air.

4. Keep surfaces flat, purposeful, and sparing.
Do not solve hierarchy by wrapping everything in cards. Use panels only when they clarify grouping or interaction boundaries.

5. Use color with discipline.
Avoid colorful UI chrome. Reserve stronger hues for status, focus, destructive actions, and key interactive emphasis.

6. Maintain parity across light and dark themes.
Both modes should preserve hierarchy, contrast, and calmness without relying on dramatically different visual identities.
