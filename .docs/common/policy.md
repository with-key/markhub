# 공통 정책서

## 1. 문서 목적

본 문서는 MVP 전 기능에 공통 적용되는 운영 및 구현 정책을 정의한다. 기능별
정책 문서보다 우선 적용되며, 별도 명시가 없는 한 본 정책을 기본값으로 사용한다.

## 2. 적용 대상

- 로그인 및 사용자 프로필
- 프로젝트
- 에픽
- 태스크
- 문서
- 태스크-문서 연결
- 문서-문서 연결
- 검색

## 3. 프로젝트 범위 정책

- 프로젝트는 최상위 작업 단위다.
- 에픽, 태스크, 문서, 연결 관계는 모두 하나의 프로젝트에 속한다.
- 프로젝트 외부 데이터 참조는 허용하지 않는다.
- 교차 프로젝트 연결은 MVP에서 허용하지 않는다.

## 4. 접근 제어 정책

- 사용자는 접근 대상 프로젝트의 멤버여야 한다.
- 목록 조회, 상세 조회, 생성, 수정, 연결, 검색은 모두 프로젝트 멤버십 기준으로
  허용한다.
- 멤버가 아닌 프로젝트의 데이터 존재 여부는 노출하지 않는다.
- 서버와 클라이언트는 동일한 접근 제한 기준을 적용해야 한다.

## 5. 저장 정책

- 핵심 데이터는 DB를 원본으로 관리한다.
- 저장은 사용자의 명시적 액션을 기준으로 처리한다.
- 저장 실패 시 사용자의 입력값은 가능한 한 유지한다.
- 클라이언트 로컬 상태는 편집 편의를 위한 임시 상태일 뿐 원본이 아니다.

## 6. 검증 정책

- 필수 입력값은 저장 전에 검증한다.
- 공백만 입력한 문자열은 유효한 값으로 처리하지 않는다.
- 상태값, 연결 대상, 프로젝트 소속 여부는 허용된 값 기준으로 검증한다.
- 유효하지 않은 입력은 저장하지 않는다.

## 7. 조회 정책

- 목록과 상세는 항상 현재 프로젝트 범위로 제한한다.
- 검색과 연결 대상 조회도 동일한 권한 및 범위 기준을 적용한다.
- 결과가 없더라도 다른 프로젝트 데이터를 대체 노출하지 않는다.

## 8. 관계 관리 정책

- 태스크-문서 관계는 다대다로 관리한다.
- 문서-문서 관계는 자기참조 관계로 관리한다.
- 관계 생성 시 양쪽 객체 모두 현재 프로젝트 소속이어야 한다.
- 관계 해제는 원본 삭제가 아니라 관계 제거 또는 비활성화로 처리한다.

## 9. 삭제 정책

- MVP에서는 프로젝트 삭제를 지원하지 않는다.
- MVP에서는 문서 완전 삭제를 지원하지 않는다.
- 관계 해제 시 원본 객체는 유지한다.
- 삭제보다 관계 해제를 우선 정책으로 적용한다.

## 10. 추적 정책

- 최소한 생성자, 수정자, 생성 시각, 수정 시각은 추적 가능해야 한다.
- 연결 생성 및 해제 이력도 추후 확인 가능하도록 저장 구조를 설계하는 것을 권장한다.

## 11. 제외 정책

- 객체 영구 삭제 플로우
- 프로젝트 간 공유 또는 연결
- 세분화된 권한 역할
- 실시간 동시 편집
- 자동 저장
